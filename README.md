# Nexus · 非线性对话画布

一个把 AI 对话从「一条时间线」变成「一张有向无环图」的聊天工具。纯前端，自带 API Key，数据全部留在本地浏览器。

**在线试用 → https://yule1048596-art.github.io/nonlinear-chat/**

站点不含任何密钥，打开后需要在设置里填自己的 API Key，Key 和对话都只存在你自己的浏览器里。

## 为什么

主流 AI 聊天软件都是线性的，于是有四个绕不开的毛病：

| 问题 | 线性聊天 | 这里怎么解决 |
| --- | --- | --- |
| **上下文污染**：问个岔路问题，主线被带偏 | 只能新开会话，丢掉全部前文 | 从任意节点拉分支，岔路和主线互不影响 |
| **分支丢失**：重新生成一次，上一版好答案就没了 | 覆盖 | 「并排重生」保留旧回答，新版本长在旁边 |
| **无法比较**：想对比两种思路 | 开两个窗口来回切 | 两条分支并排放在画布上，一眼看完 |
| **无法汇合**：A 分支和 B 分支各得到一半结论 | 手动复制粘贴 | 一个节点可以有**多个父节点**，两条分支的结论自动合进同一个上下文 |

最后一条是关键，也是「树形分支」做不到、必须上 DAG 的原因。

## 核心机制

画布上是**图**，发给模型的必须是**序列**。中间那层转换在 [`src/lib/context.ts`](src/lib/context.ts)：

1. 从当前节点出发，向上收集**全部祖先**（多条路径到达同一个祖先只算一次）
2. 对这个子图做**拓扑排序**（Kahn 算法），保证父节点永远排在子节点前面
3. 就绪节点之间按 `createdAt` 择早优先 —— 于是多条分支合并时会按真实发生的时间交错，每条分支内部的因果顺序不被打乱
4. `system` 节点抽出来合并成一条 system 消息，`note` 节点默认跳过，空节点和出错节点跳过

第 4 步里「跳过空节点」有个额外好处：**首次生成和重新生成走的是同一条代码路径** —— 重新生成前先把节点内容清空，它就自动把自己排除在上下文之外了。

选中任意节点时，不在它上下文里的节点会整体褪成灰色，底部状态条同时显示「这一发会带多少条消息、多少字符」。非线性对话最容易失控的就是上下文，所以这是界面上唯一的强视觉信号——其余一切都为它让路：节点的操作按钮默认隐藏，悬停或选中才浮现；模型名、token 数这类元信息同理。画布上放二三十个节点也不会变成按钮墙。

## 接哪些模型

任何实现了 OpenAI `/chat/completions` 协议的服务都能接。设置里内置了这些预设，选一个就自动填好 Base URL：

OpenAI · DeepSeek · OpenRouter · 硅基流动 · Moonshot · 智谱 GLM · 本地 Ollama

可以存**多套配置**，在不同分支上用不同模型，横向对比效果。推理模型（DeepSeek-R1 等）的 `reasoning_content` 会单独折叠显示，且不进入下一轮上下文。

### CORS 提醒

浏览器直连模型厂商，所以对方必须允许跨域。DeepSeek、OpenRouter、硅基流动等都没问题。本地 Ollama 需要启动时加环境变量：

```bash
OLLAMA_ORIGINS=* ollama serve
```

如果连不上，「测试连接」会直接告诉你是 CORS、Key 错了、还是 Base URL 写错了。

## 操作

| 操作 | 效果 |
| --- | --- |
| 双击画布空白处 | 新建一个游离节点 |
| ⌘/Ctrl + Enter | 在提问节点里直接发送 |
| 拖节点底部圆点 → 另一个节点顶部 | 加一条上下文来源（这就是「多父」） |
| 点击底部圆点，再点目标顶部圆点 | 同上，不用拖 |
| 选中节点 | 高亮它会带上的全部上下文，其余节点褪灰 |
| 顶栏 ◑ 按钮 | 主题在「跟随系统 → 亮色 → 暗色」之间循环 |
| 追问 | 在回答下面接一个新提问 |
| 重生 | 就地重新生成（覆盖当前内容） |
| 并排重生 | 保留旧回答，旁边生成新版本 |
| 在已有回答的提问上再点「发送」 | 并排生成新回答，**不会覆盖**已有内容 |
| Shift + 点 ✕ | 连同所有下游节点一起删 |
| 选中连线按 Backspace | 断开这条上下文来源 |

连线成环会被拒绝（成环就没法拓扑排序了），拒绝时底部会给出提示。

## 数据

全部存在浏览器 IndexedDB 里 —— API Key、画布、设置，都不经过任何第三方服务器。

代价是**清浏览器数据会一起清掉**，重要画布记得用顶栏「导出」存成 JSON。导入时会重新分配节点 id，所以同一个 JSON 可以反复导入而不会撞车。

## 部署

站点挂在 GitHub Pages 上，源是 `gh-pages` 分支。重新发布：

```bash
npm run deploy
```

脚本会构建、把 `dist/` 推到 `gh-pages`，一两分钟后线上生效。

仓库里还有一份 `.github/workflows/deploy.yml`，配置的是「推送到 main 就自动跑测试并部署」。要启用它得先给 CLI 令牌加 workflow 权限（GitHub 不允许 OAuth App 在没有这个权限时创建工作流文件）：

```bash
gh auth refresh -h github.com -s workflow
```

之后把工作流文件提交推送，再到仓库 Settings → Pages 把 Source 改成 GitHub Actions，`npm run deploy` 就可以不用了。

## 一些实现上的坑

- **React Flow 的双击缩放会 `stopPropagation`**，把 `onDoubleClick` 吃掉。必须 `zoomOnDoubleClick={false}` 才能做「双击建节点」。
- **流式输出时每个 token 都 setState 会拖垮画布**。这里做了两层：节点内容更新节流到 ~30fps；React Flow 的节点对象按 id 缓存，只有位置/选中态变了才换新对象，内容变化由 `MessageNode` 自己订阅 store 消化。
- **纯防抖存盘在流式输出时永远不会触发**（token 一直在来，计时器一直被重置）。`createDebouncedSaver` 带 `maxWait`，最多攒 3 秒就强制落一次盘。
- **页面在流式输出中途被关掉**，节点状态会卡在 `streaming`。加载时统一洗成 `idle`。
- **受控模式下 React Flow 不会把量到的节点尺寸写回你的节点对象**，只通过 `onNodesChange` 的 `dimensions` 变更告诉你一次。小地图判断「节点有没有尺寸」看的正是 `node.measured`，丢了这个变更小地图就一个节点都不画（连线不受影响，它读的是内部测量值）。
- **悬停才出现的操作条必须始终占位**，否则悬停瞬间节点高度变化，连线会跟着抽动。用 `opacity` 而不是 `display` 控制。
